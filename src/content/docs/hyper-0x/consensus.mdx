Hyper 0X uses a hashgraph-style, **asynchronous Byzantine fault tolerant (aBFT)** consensus. It stays safe as long as fewer than one third of validators are faulty.

## How it works

1. **Event:** a validator wraps new transactions in a signed event. The event holds two hashes: its own last event and the last event a peer sent it.
2. **Gossip about gossip:** validators sync with random peers, so the graph itself records who heard what, and when.
3. **Virtual voting:** no votes are sent over the network. A witness becomes "famous" once more than two thirds of validators strongly see it.
4. **Consensus order:** each event's timestamp is the median of the times validators first received it.

## Attacks it blocks

| Attack                               | Why it fails on Hyper 0X                                                                  |
| ------------------------------------ | ----------------------------------------------------------------------------------------- |
| 51% attack and double-spend by reorg | Validators are named institutions and finality is deterministic                           |
| Sybil                                | Keys are bound to PKI, so an unknown identity gets no vote                                |
| Leader DDoS or censorship            | There is no leader to target                                                              |
| Front-running (MEV)                  | Order comes from the median receive time, so no single node can move a transaction ahead  |
| Eclipse                              | Peers are picked at random from a known set, over mutually authenticated post-quantum channels |

## Compared with other chains

|                           | Finality                                   | Who orders                   |
| ------------------------- | ------------------------------------------ | ---------------------------- |
| Proof of Work (Bitcoin)   | Probabilistic, about 60 min                | The block's miner            |
| Proof of Stake (Ethereum) | About 13 min                               | The slot's proposer          |
| Leader BFT (HotStuff)     | Deterministic, after a vote round          | The round's leader           |
| **Hyper 0X**              | Deterministic, once virtual voting decides | No single node (median time) |

## What we changed from classic hashgraph

- Permissioned validators; joining or leaving takes a threshold vote on-chain.
- Post-quantum gossip using ML-KEM-768 + X25519.
- A policy engine in the transaction path for approvals, holds and corrections.
- Each party's data stays encrypted to that party alone.
- L2 hooks: L2s post their state roots as ordinary events.
